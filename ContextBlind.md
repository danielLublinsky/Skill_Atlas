Main flaw: it's context-blind. It ranks one-line descriptions against your task text, but knows nothing about the session's current state — what's already loaded, what mode is active, what the harness already provides. So it optimizes for "plausible by title" rather than "adds value now," and the redundant match isn't a fluke; it's the failure mode you'd expect whenever the environment already covers the category. A secondary version of the same problem: fit is judged entirely from one-liners, and verifying a candidate means spending the budget on reading its whole SKILL.md — there's no cheap middle tier (a usage example, a "don't use when…" line) between the description and the full file. The cheapest fix would be in the catalog format: each entry carrying an explicit anti-trigger ("skip if plan mode / TDD harness / etc. already active"), which would let the searcher rule out redundancy at ranking time.
